The world API, in five minutes

You never touch the terminal. You send deeds — named intents like move, eat, kick, pray — and the world answers with what happened and what the explorer now perceives. Nothing you couldn't see is ever revealed: no glyphs, no map cells, no menus, no keystrokes on the wire.

Lifecycle

client  ──► new_game {name, seed?, role?, race?, gender?, align?}
         ◄── {sessionId, observation}
client  ──► act {sessionId, action: "move", direction: "south"}
         ◄── {outcome, events[], observation, decision?}
client  ──► act {sessionId, replyTo: "decision-3", item: {id: "item-a"}}
         ◄── {outcome, events[], observation}
client  ──► get_state {sessionId}     (a look costs no turn, consumes nothing)
client  ──► resume {sessionId}        (re-enter a persisted world)
client  ──► end_session {sessionId}   (leave it behind)

Every reply carries

fieldwhat it is
outcomewhat the deed did: completed, needsChoice, cancelled, invalidTarget, interrupted — plus turn cost, and the durable result when the world ends
eventsindividual world changes, in order: saw / felt / heard / shown
observationthe full visible world: turn, you, named vitals, world [{x, y, kind, mark, color}] (terrain / creature / ally / object / remains / effect / you), heard
decisionat most one pending genuine choice: item, selection, confirmation, or text — answered with replyTo, cancellable, idempotent on retry

Persistence & resume

The session input log plus the starting seed is the save: replay it into a fresh world for an identical resume, then play continues live. Retries are safe: revision checks and idempotent answers mean a timed-out prayer never prays twice.

Normative contract: API_DESING.md in the repo. Full JS reference and every world→UI event, with shapes: /api-docs. Raw engine protocol (the layer below the world): proto/PROTOCOL.md. If the docs and the world disagree, the world wins and the docs are a bug — file it.
